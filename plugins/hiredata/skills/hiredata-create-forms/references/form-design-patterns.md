# Recruitment form design patterns

## Core rules

- Ask only for information that changes a decision or next action.
- Prefer one clear question per field.
- Use helper text to explain format or why information is needed, not to repeat the label.
- Use choice fields for known decision paths and free text for genuinely open input.
- Make the central decision field required; make supporting context optional unless operationally necessary.
- Mirror the language and tone of the preceding message unless the user specifies otherwise.

## Common patterns

### Availability

Start with current availability. Branch available or soon-available candidates into timing and preferences. Useful follow-ups may include desired roles, availability date, salary expectations, and travel range, but include only fields relevant to the workflow.

### Screening

Place decisive eligibility questions early. Branch ineligible responses to a respectful ending and eligible responses to deeper questions. Avoid collecting unnecessary sensitive data.

### Feedback

One rating plus one optional explanation is often sufficient. If a quick-reply message already captured the rating, the linked form should ask for the explanation rather than repeat the score.

### NPS

Use a 0–10 score. Ask a concise follow-up appropriate to the score, and specify who reviews low scores and how quickly.

### Consent

State the purpose, scope, retention or policy reference, and whether submission is optional. Consent requirements depend on purpose, jurisdiction, and the customer's lawful basis; do not infer them solely from whether a person already exists in the ATS.

## Branch test

For every conditional field, test:

1. expected positive answer;
2. expected negative answer;
3. no answer when optional;
4. unexpected or changed answer;
5. whether the destination exists and the ending matches the answer.
