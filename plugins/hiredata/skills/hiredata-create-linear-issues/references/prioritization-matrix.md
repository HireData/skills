# HireData issue prioritization matrix

This reference summarizes the team matrix as of 2026-08-15. The canonical source is the [Published Issue Prioritisation Manifest](https://www.notion.so/2d200d874868804d8e63fc721309adce) in the SOP database.

**Process owner:** Desi. Propose policy changes against the published source rather than creating a second working copy. When the live page and this cached summary differ, follow the published page and flag that this reference needs refreshing.

## Urgent

Use when there is severe disruption to a core product or critical workflow, such as:

- outage or core application unavailability;
- surveys or WhatsApp delivery being completely broken;
- widespread failed automation runs;
- app-connection failure preventing work;
- data corruption or a security incident.

The published matrix also classifies issues affecting **key clients or partners**—with Carerix given as an example—as Urgent and requiring immediate attention. Verify key-client or partner status against a current approved source. If no authoritative source is available, ask the Triage/process owner before assigning Urgent. Never infer key status from the customer name, company size, or a stale list. Record the impact, reach, workaround, and time sensitivity so the priority remains explainable.

## High

Use for significant functional or UX impact while the application remains usable, such as:

- a highly inconvenient workaround;
- an important customer workflow or automation being materially impaired;
- widespread slowness or timeouts;
- a major feature that works only partially for a meaningful user group.

## Medium

Use for moderate impact that does not block critical work, such as:

- minor feature failures or confusing UX;
- performance issues affecting a small group or edge case;
- a straightforward workaround;
- a client-requested feature that is partially missing and tied to a KPI, without immediate operational blockage.

## Low

Use for minimal workflow impact, such as:

- copy, alignment, icon, or other cosmetic defects;
- non-critical optimizations;
- nice-to-have improvements without immediate demand;
- rare edge cases with low consequences.

## Safeguards

- Retain the current priority when rewriting an existing issue unless impact changed or reprioritization was requested.
- Do not infer priority from tone, customer size, or an arbitrary deadline.
- If genuinely unsure, the reporting SOP permits Medium; record the uncertainty and reasoning in a comment.
